Subject: [PATCH 0/2] platform/x86: toshiba_acpi: support Dynabook Portege X40-K (DNBK0001)

Dynabook is the spun-off Toshiba PC division and its firmware still implements
the Toshiba HCI/SCI protocol verbatim, under ACPI device \_SB.VALZ with
_HID "DNBK0001". The in-tree toshiba_acpi driver implements this exact
protocol but its ACPI match table only lists Toshiba-era IDs (TOS1900, ...),
so it never binds on these machines.

On a stock kernel that means:
 - no keyboard-backlight device in /sys/class/leds, and
 - Fn brightness / keyboard-backlight keys produce no usable events
   (intel_backlight itself works fine, so the panel is not the problem).

Patch 1 adds the DNBK0001 id so the driver binds and exposes the hardware.
Patch 2 fixes a separate hotkey bug: on info_supported machines the driver
reads the EC event FIFO only once per SCI Notify, while the EC enqueues a
press+release pair per key and coalesces rapid presses; leftover entries then
replay on a later keypress (hotkeys "bleeding" into one another). Drain the
FIFO fully per Notify, mirroring the existing HCI_SYSTEM_EVENT path.

Both changes are minimal and have been tested on a Dynabook Portege X40-K
(CachyOS, clang-built 6.11-era kernel). Keyboard backlight and all Fn hotkeys
now work correctly, including under rapid consecutive presses.

Hans, Ilpo — I can send these as two separate patches if you prefer; I've kept
them as a small series here for context. Happy to rebase / split as needed.
